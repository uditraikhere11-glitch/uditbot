## [14.0.1-rc.1] - 2026-11-04
- **Release Identifier:** `AB-V14-P0-RECONCILE-VERSION-CONTROL-01`
- **PR Title:** `AB-V14-P0-RECONCILE-VERSION-CONTROL-01 — Durability, Cancel Liveness & Version Governance`
- **Parent GitHub Baseline (`origin/main`):** `29c6515b8ce448ff54bf1f3024f2e7c9027c8896` (PR #38 merged)
- **P0-01 (Durable-First Exit Accounting & Closure Gate):** Separated broker-observed external tradebook fills (`broker_observed_exit_filled_qty`) from canonical durable SQLite accounting (`exit_filled_qty` sourced from `JournalDB.get_position_accounting`). Any exception or write failure in `JournalDB.record_fill()`, `get_position_accounting()`, or `upsert_position_lifecycle()` transitions the position to `RECONCILIATION_REQUIRED` (`persistence_uncertain=True`), stages uncommitted fills for idempotent replay on recovery/restart, halts new entries via `gate.halt_new_entries()`, and suppresses `POSITION_CLOSED` transitions and notifications until SQLite commit succeeds.
- **P0-02 (Authoritative LIVE Trade Retrieval Without Test-Mock Shortcuts):** Removed the `self.__dict__` instance-method check from `DhanClient.get_trades_for_order()` in `src/broker/dhan_client.py` so `LIVE` mode (and `bypass_test_mode=True`) always queries the authoritative `GET /v2/trades/{order-id}` endpoint and never synthesizes `OK_EMPTY` from instance method overrides. Moved all HTTP transport mocking (`session.get`) into the test suite and added regression tests proving overridden `order_status` never suppresses `get_trades_for_order()` and genuine `OK_EMPTY` responses remain strictly distinguishable from `FAILED`, `MALFORMED`, and `UNAVAILABLE` reads.
- **P1-02 (Bounded Per-Leg Orphaned Cancellation State Machine):** Added durable per-leg cancellation tracking (`orphaned_leg_cancel_details` and `orphaned_leg_cancel_states`) across `REQUESTED`, `ACK_UNKNOWN`, `REJECTED`, `CONFIRMED_TERMINAL`, and `MANUAL_INTERVENTION_REQUIRED` with configurable ACK timeout (`10s`), exponential retry backoff (`5s` base), max attempts (`3`), and wall-clock deadline (`60s`). Escalates unresolved legs to `MANUAL_INTERVENTION_REQUIRED` with a single deduplicated alert while allowing subsequent broker terminal confirmation to resolve the state.
- **P1-03 (Fail-Closed Release Version Governance):** Eliminated `except Exception: pass` in `verify_release_version_governance()` (`src/version.py`). Explicit `--base-ref` now strictly requires a valid Git working tree, resolvable `HEAD` and `<base-ref>` commits, successful `git merge-base`, successful `git diff`, and verified SemVer increment whenever code files change.
- **P1-04 (Reviewed WebUI Contract & Safety Invariants):** Reviewed `src/setup_app.py` and `src/setup_wizard.py` against `29c6515b` and updated `test_18_original_web_setup_workflows_remain_operational` and `test_20_web_setup_files_remain_byte_for_byte_original` to validate both the reviewed `src/setup_app.py` SHA-256 and WebUI behavioral contracts (CSRF 403 enforcement, localhost default bind, secret non-disclosure, `FNO_PRICE_MARKUP_PCT`, and version namespace separation).
- **P1-05 (Python 3.11 / 3.12 / 3.13 CI Matrix & Pydantic `ClassVar` Compatibility):** Updated `.github/workflows/ci.yml` to run across Python `3.11`, `3.12`, and `3.13`, including fail-closed `--base-ref` negative checks and both independent merge-gate suites (`tests.test_auditbot_v14_release_blockers` and `tests.test_ab_v14_merge_gate_extra`).
- **P1-07 & NET-ISOLATION-01 (Complete Lifecycle Offline Network Isolation in `tests/__init__.py`):** Enforced network attempt clearing and swallowed-attempt detection in `tests/__init__.py` across all 10 `unittest` execution boundaries (`setUp`, `testBody`, `tearDown`, `addCleanup`/`_callCleanup`, `setUpClass`, `tearDownClass`, `addClassCleanup`/`doClassCleanups`, `setUpModule`, `tearDownModule`, and `addModuleCleanup`/`doModuleCleanups`) with zero network-guard code in production modules (`505/505` tests passing offline).
- **P0-A / P0-B / P0-C / P1-D & Source Allowlist Preservation:** Preserved strict parent-linked SELL fill attribution, per-leg terminal confirmation, no fabricated `TARGET_LEG` on parent `CLOSED`, Pydantic `ClassVar` candidate validation, and fail-closed `LOG_GROUP_ID` / `MONITORED_CHANNEL_IDS` / `TEST_GROUP_ID` overlap rejection (`run.py` untouched at `e27af75592503e4861204c2db759db5c3583865c`).
